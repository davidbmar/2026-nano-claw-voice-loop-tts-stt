/calls Panel: Provider Truth, Durable Phone Settings, Detailed Costs

2026-07-26 · branch call-review-panel · markdown source: design.md

Context

Reviewing a live call, David suspected the phone line's TTS was secretly Google ("sounds like Gemini 3.1") despite the panel implying LuxTTS, and asked to fix the attribution, do the same for STT, and improve the per-call cost breakdown. He also observed the console at nano.chattychapters.com has phone settings the line "doesn't seem to be taking."

Investigation established the ground truth:

  • Audio is genuinely local. TTS: voice id → voice_catalog engine → voice/tts.py:279-303 (luxtts→:8301, kokoro→:8300, piper in-process). STT: local faster-whisper (:8200, size from NANO_CLAW_PHONE_STT_SIZE=medium). There is no cloud TTS/STT code in the repo.
  • But the words can be Gemini's. The conversation LLM falls back ollama/gemma4:e2b → gemini/gemini-flash-lite-latest → claude-haiku-4-5 on a 4s first-token timeout (src/providers/index.ts:170-183,222-258), and nothing records which model actually served a turn — debug.model in the SSE stream is the requested model (src/api/server.ts:577,941). The ear-test was likely catching fallback turns; today that's unverifiable.
  • Settings amnesia is real. Console phone settings (voice/model/speed/STT size/speech-prep via /api/phone/config, VAD via /api/phone/vad) live in in-memory maps (voice/phone.py:184-190,304-318) wiped on every container restart — the watchdog restarted the stack twice on 2026-07-26 alone. NANO_CLAW_PHONE_MODEL/SPEED are also missing from run.sh's env passthrough (:290-315).
  • Cost rows discard detail. cost_ledger accumulates by (component, unit_kind, model) but drops model on write (voice/cost_ledger.py:62-69,729-740); the panel renders raw floats with no labels (voice/web/calls.html:520-558).
Decisions (locked with David): persist settings to the data volume; keep the LLM fallback chain but surface per-turn attribution; per-component + per-model cost detail.

Workstream A — Served-model attribution (TS + Python)

  1. src/types.ts — add model?: string to LLMResponse (:165) and the done StreamEvent variant (:224-228).
  2. src/providers/index.ts — in complete() (:196-224) return {...response, model: m} per attempt; in completeStream() (:232-260) wrap each attempt's generator, adding model: m to done events. (Keeps fallback.ts pure.)
  3. src/api/server.ts — capture served model in the streaming loop (:925-928); DebugInfo (:65-118) gets model = served model and new requestedModel? set only when it differs; both build sites (:577, :941). tool_pending emitters reuse the same debug object.
  4. voice/phone.py _stream_reply (:872-1046) — capture debug.model/debug.requestedModel from SSE final/tool_pending events (and the non-stream JSON fallback :929-936); emit model, modelRequested, modelFallback on the assistant_turn event (:1033-1043). Scheduler branch (:836-852) adds model from the runner's _model attr.
  5. call_start payload (:445-457) — add sttSize, speed, model, catalog engine so every call is self-describing.

voice/cost_ledger.py:918-931 already reads debug.get("model") into the ledger accumulation key — the TS fix flows into cost attribution with no extra work.

Workstream B — Durable phone settings

  1. voice/phone.py: _SETTINGS_KEYS = {VOICE, MODEL, SPEED, STT_SIZE, SPEECH_PREPARATION} + persist VAD (NANO_CLAW_PHONE_VAD) in the same file. Path via NANO_CLAW_PHONE_SETTINGS_PATH, default /app/data/phone-settings.json. Shared validators between POST handler and loader. _load_persisted_overrides(): unknown keys ignored, bad values dropped (one warning each), any exception leaves overrides untouched — a corrupt file can never brick call handling; called from register_phone_routes after the phone_enabled() gate. _persist_overrides(): atomic tmp + os.replace, best-effort; write-through from the config and VAD POST handlers; a cleared model persists as absence.
  2. run.sh passthrough block (:290-310) — add -e NANO_CLAW_PHONE_MODEL and -e NANO_CLAW_PHONE_SPEED. Precedence: persisted console overrides > .env > code default (how _cfg already works).

Workstream C — Cost breakdown with details

  1. voice/cost_ledger.py: model TEXT DEFAULT '' in _SCHEMA + idempotent migration in ensure_schema via PRAGMA table_info guard (live-volume safe; old rows read back '' → "unattributed"). LedgerEntry gains model; write_call writes it; finish_call stops dropping the accumulation key's model. Phone tracking: STT rows whisper/<stt_size>; TTS rows <catalog engine>/<voice_id> (e.g. luxtts/lux_george; in-process piper fallback inside tts.py is not distinguished — documented caveat). New component_meta(): pricing labels/colors/math per ledger component, {} on failure.
  2. voice/call_review.py timeline_handler (:126-146) — add "costMeta": cost_ledger.component_meta().
  3. voice/web/calls.html: call_start renders a Providers line (TTS engine/voice · STT whisper/size · VAD · codec · speed · model); agent bubbles get a model chip with a distinct "(fallback)" style; renderCost rewrite — component groups (label + color swatch) → per-model subrows, formatted units ("41.6s audio", "1,843 chars", "12.3k in / 800 out"), "unpriced" marker instead of silent $0, note that telephony + infra bill the same connected minutes, total row kept.

Tests

  • New test_phone_settings_persistence.py: POST writes file; fresh load restores exactly known keys; unknown/bad/corrupt handling; cleared model stays cleared.
